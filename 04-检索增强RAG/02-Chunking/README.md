## 文档分块

### 一、为什么要文档分块
- **技术层面**：无论是嵌入模型还是大模型，它们的上下文长度都是有限的，不能将加载的整个文档扔进去，需要将文档切分成**合适大小**的**块（chunk）**
- **业务层面**：用户问的问题只是与整个知识库中某个块中的内容有关，只需要附带与问题相关的文档就行。如果将整个文档扔给大模型，会导致 token 消耗量增加、处理速度变慢、引入过多的噪声（无关内容）

> 块大小核心矛盾 <br>
> - 块大： 信息量多 -> 向量语义越泛化
>   - 优点：上下文完整
>   - 缺点：噪声多，检索精度低；过大可能超出嵌入模型和大模型的上下文限制
> - 块小 -> 信息量少 -> 向量语义越精准
>   - 优点：语义精准，检索精度高
>   - 缺点：缺少上下文；过小可能导致一句话在中间截断，语义不完整；检索时匹配很多碎片化信息，难以拼出完整答案
