## 查询优化

### 要解决的问题
- 用户提问常常口语化、表达过于简略或含糊，与实际业务不匹配
- 用户问题与知识库中的原始文档存在巨大的表达差异
- 用户问题十分复杂，大模型需要推理分解多个步骤才能完整，但是有些大模型不具备推理能力

### 查询优化方法
查询优化的目标是**完善用户的问题，提升用户意图理解的准确性**，包括：
- **Enrich完善问题**：通过大模型引导完善用户问题，产生一个更利于系统理解的完善后的用户问题。
- **多路查询（Multi-Query）**：针对用户问题生成多个相关问题，分别检索后汇总结果。
- **问题分解（Decomposition）**：将复杂问题拆分为多个子问题，依次或并行同步解决所有子问题从而获取最终答案。

其他查询优化方法还包括：

| 优化方向         | 目标 | 典型方法 |
|--------------|---|---|
| **让问题更清楚**   | 把口语化、模糊、指代不清的用户提问转成检索系统更容易理解的形式 | 查询重写、查询规范化、上下文补全、对话重写、查询压缩、意图识别与槽位填充 |
| **让查询更丰富**   | 扩大召回范围，避免因为表达太窄而漏掉关键文档 | 查询扩展、同义词扩展、多路查询、HyDE、Query2Doc、伪文档生成 |
| **让复杂问题可执行** | 把一次性难以回答的问题拆成可检索、可推理、可迭代执行的步骤 | 问题分解、Step-Back、多跳检索、迭代检索、子查询并行、假设性查询 |
| **让查询走对路径**  | 根据问题类型选择最合适的知识库、索引或检索策略 | 查询路由、查询分类、元数据过滤路由、混合检索路由、自适应检索、工具/数据源路由 |
