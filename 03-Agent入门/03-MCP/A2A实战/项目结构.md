#  **python-a2a 版**

同一套「客服主管 + 两个专员」的 A2A 多智能体案例， **`python-a2a`** 实现了一遍。

原版完整保留在上一级目录，两版可以并排对照。

---

## 一、文件结构

```
python-a2a版/
├── agent_return.py      # 退货专员      服务端，监听 8003
├── agent_shipping.py    # 物流专员      服务端，监听 8004
├── supervisor.py        # 客服主管      客户端（不监听端口）
├── llm_client.py        # 共享 DeepSeek 客户端
└── requirements.txt
```

---

## 二、为什么要做这个对照

A2A 是**协议/契约**，规定的是行为语义（名片怎么发现、任务怎么流转、怎么传）。
具体某个 Python 库只是这份契约的一种**实现方言**。

这个案例最有教学价值的点就是：**换了库，系统架构没变，但接线方式全变了。**
学生能直观看到「哪些是协议要求、哪些只是某个库的实现选择」。

## 三、核心概念对照表

| 【三大核心】 | 官方 `a2a` SDK | `python-a2a` |
|---|---|---|
| **【名片】对象** | `AgentCard(...)` | `AgentCard(...)` |
| 【名片】地址字段 | `supported_interfaces=[AgentInterface(url=..., protocol_binding="JSONRPC")]` | `url="http://localhost:8003"` 直接写在卡片上 |
| 【名片】能力字段 | `AgentCapabilities(streaming=..., push_notifications=...)` | `capabilities={"streaming": ..., ...}` 普通 dict |
| 【名片】技能字段 | `AgentSkill(id=..., name=..., description=..., tags=[...])` | `AgentSkill(name=..., description=..., tags=[...], examples=[...])`（无 `id`，用 `name` 当标识） |
| 【名片】发现路径 | `GET /.well-known/agent-card` | `GET /.well-known/agent.json` |
| **【任务】服务端扩展点** | 继承 `AgentExecutor`，实现 `execute(context, event_queue)` | 写一个普通函数 `handler(message) -> message` |
| 【任务】取用户输入 | `context.get_user_input()` | `message.content.text` |
| 【任务】回传结果 | `event_queue.enqueue_event(new_text_message(...))` | 直接 `return Message(...)` |
| 【任务】绑定会话 | 手动传 `context_id` / `task_id` | `parent_message_id` / `conversation_id` |
| 【任务】任务存储 | 显式注入 `InMemoryTaskStore()` | `A2AServer` 内置 `self.tasks` |
| 【任务】请求处理器 | 显式 `DefaultRequestHandler(...)` | `A2AServer(agent_card=..., message_handler=...)` |
| **【传输】路由注册** | 手工拼 `create_agent_card_routes()` + `create_jsonrpc_routes()` + `create_rest_routes()` | 框架自动注册，无需写 |
| 【传输】Web 框架 | Starlette + uvicorn（**ASGI / 异步**） | Flask + werkzeug（**WSGI / 线程**） |
| 【传输】调用风格 | JSON-RPC（`POST /`） | REST 风格（`POST /`） |
| 【传输】启动 | `uvicorn.run(app, host=..., port=...)` | `run_server(server, host=..., port=...)` |
| **客户端** 创建 | `await create_client(url, ClientConfig(streaming=False))` | `A2AClient(url)`（一行） |
| 客户端 发消息 | 构造 `SendMessageRequest` + `async for` 遍历流 + `get_stream_response_text()` | `client.ask(文本)`（一行） |
| 客户端 关闭 | `await client.close()` | 无需显式关闭 |
| 客户端 并发模型 | `async def` / `asyncio.run()` | 普通同步函数 |
| 多专员注册 | 自己维护 `AGENTS = {name: url}` 字典 | `AgentNetwork` 注册表（还能列出发现结果） |

## 四、没变的 vs 变了的

**没变的（协议层面的「契约」）**
- 三大核心的概念划分：名片 / 任务 / 传输，两边都得有
- 名片的作用：让客户端**动态发现**专员，而不是靠硬编码
- 端口的角色分工：专员是服务端（监听端口），主管是客户端
- 业务逻辑与协议解耦：提示词、LLM 调用完全不因换库而改变
- 路由策略（LLM 意图分类）与 A2A 协议无关，原样保留

**变了的（实现层面的「方言」）**
- 名片发现路径：`agent-card` → `agent.json`
- 传输风格：JSON-RPC → REST 风格
- Web 框架：ASGI/async → WSGI/线程
- 服务端扩展点：继承类 → 传函数
- 任务存储：显式注入 → 框架内置
- 客户端调用：构造请求+遍历流 → 一行 `ask()`

## 五、运行

两个专员各占一个终端（**必须先启动**，否则主管的服务发现会连不上）：

```bash
cd a2a-class-demo/python-a2a版
D:\llmsvirtulenv\a2a_customer\Scripts\python.exe agent_return.py      # 8003
D:\llmsvirtulenv\a2a_customer\Scripts\python.exe agent_shipping.py    # 8004
```

再开一个终端跑主管：

```bash
D:\llmsvirtulenv\a2a_customer\Scripts\python.exe supervisor.py
```

需要环境变量 `DEEPSEEK_API_KEY`（两个专员和主管都要用大模型）。

## 七、踩坑记录（换库时真实遇到的）

### 1. `AgentCard.url` 里**不要**带 `/a2a`

`A2AClient` 发现名片时按顺序试：

```
{url}/.well-known/agent.json     ← 先试这个
{url}/agent.json
{url}/a2a/agent.json
```

而 `python-a2a` 的 `A2AServer` 把**人类可读的 HTML 说明页**挂在了 `/a2a` 和
`/a2a/.well-known/agent.json` 上，只有 `/.well-known/agent.json` 和 `/agent.json`
才返回干净的名片 JSON。

所以一旦 `url` 写成 `http://localhost:8003/a2a`，客户端第一个探测到的就是 HTML 页面，
它只能从 HTML 里勉强抠出一个残缺名片 —— 表现是
**`name` / `description` 正常，但 `skills` 是空的**（很隐蔽，不报错）。

正确写法：`url="http://localhost:8003"`（裸地址）。

### 2. `capabilities.streaming` 写了 `False` 也会变 `True`

`A2AServer.__init__` 会强制把 `agent_card.capabilities["streaming"]` 置为 `True`
（因为它确实提供 `/a2a/tasks/stream` 这个 SSE 端点）。写 `False` 会被覆盖。
`push_notifications` 则不会被覆盖。

### 3. 同步 vs 异步不只是 API 名字的事

官方 SDK 是 ASGI，`llm_client.py` 用 `AsyncOpenAI` + `async def chat()`；
`python-a2a` 是 WSGI/Flask，`message_handler` 是**同步**调用，没有运行中的事件循环。
所以本版的 `llm_client.py` 改成了同步 `OpenAI` + `def chat()`。
硬要在同步 handler 里用异步客户端，要么报错、要么得 `asyncio.run()` 包一层，反而绕。
